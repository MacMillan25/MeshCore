## Git: правила работы

- Рабочая ветка — **`darktec`** (переименована из `feat/darktec-e22p` 18.10.2026: E22 и E22P давно собираются из одной прошивки, старое имя врало). `main` — релизная ветка форка, туда не пушить.
- `origin` = <https://github.com/MacMillan25/MeshCore.git> — сюда идёт вся работа.
  `upstream` (`beeline09/MeshCore`) и `mc` (`meshcore-dev/MeshCore`) — только для чтения, не пушить.
- **В начале каждой сессии:** `git fetch --all --prune` и подтянуть актуальное, прежде чем что-то править.
- **Закончил задачу — сам закоммить и сам запушь** в `origin`, не дожидаясь просьбы. «Сохрани» / «залей» / «закинь на гит» — это коммит плюс push.
- **Релиз прошивки — только по явной просьбе.** Коммит и push в `origin` делаются сами; тег `darktec-v1.18.0dN` и выкладка восьми UF2 (`tools/make_release.py`) — только когда Андрей попросил выложить прошивку.
- Перед переключением ветки или перезаписью файлов проверить, нет ли незакоммиченных правок.
- Никогда не делать `git clean -fdx` и подобную массовую зачистку, не убедившись, что там нет чужой работы.
- Заканчивать сессию чистой рабочей папкой (`git status`), чтобы следующая машина не спотыкалась.
- Коммиты — в стиле истории: `fix(darktec): …`, `feat(darktec): …`, `docs: …`, `chore: …`.

### Транспорт к GitHub

Способы проверять, а не предполагать — они различаются по машинам и окружениям.

- **Если TLS падает** с `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS` — переключить бэкенд:
  `git config http.sslBackend openssl` (локально в репозитории, не `--global`).
- **Если `git push` падает** с `could not read Username for 'https://github.com'` или зависает — пушить скриптом:
  ```
  python tools/git_push.py                 # текущая ветка
  python tools/git_push.py <ветка>         # указанная ветка
  ```
  Скрипт берёт токен у `gh`, а если `gh` нет — у Git Credential Manager, и подставляет его в URL ровно на один `git push`. Токен не сохраняется и вычищается из вывода.
- **Подпись коммитов** проверять в первую очередь. Если `git commit` падает с «Author identity unknown» — задать `user.name` / `user.email` локально (`git config`, без `--global`). Эти значения в файл не вписывать.
- **После push проверить, что дошло:** `git rev-parse HEAD` против `git rev-parse origin/darktec`. Зависший push не отправляет ничего, хотя выглядит как «команда думает».
- **Никогда не оставлять токен в `.git/config`.** Если без токена в адресе никак — только на одну команду, потом сразу проверить конфиг.

### Если `git status` показывает сотни изменённых файлов

Сначала проверить, а не коммитить. Обычно это переписанные переводы строк.

- Сравнить хеши без фильтров: `git hash-object --no-filters -- <файл>` против `git rev-parse HEAD:<файл>`. Совпали — правок нет.
- Если различаются только переводы строк — `git add --renormalize -- <файлы>`, а не перезапись файлов.
- Держать `core.autocrlf=false` в этом репозитории: с `true` рабочее дерево вечно выглядит грязным.

## Проект DarkTec

Железо: **nRF52840 + SX1262**, модули E22 / E22P, дисплей SSD1306 128×64 (I2C), INA3221, GPS, буззер. Прошивка на C++ под Arduino framework, сборка PlatformIO. Версия — **1.18.0**, база — beeline09 `south_edition` (коммит `83f2b0b4`). Радио по умолчанию: **869.900 МГц**, 62.5 кГц, SF8, CR8, 22 dBm.

**Главное правило: любая правка, касающаяся модуля или железа, делается ОДИНАКОВО для всех ролей и всех модулей.**

- **8 ролей = 8 env.** Радиомодуль больше не выбирается сборкой: E22-900M33S, E22-900M30S, HT-RA62 и E22P-868M30S работают из одной прошивки.
- Модуль выбирается в подменю `[ Darktec ]` компаньона или командой CLI `set radio.module 0-3` и применяется на лету:
  - `0` = E22-900M33S, `1` = E22-900M30S, `2` = HT-RA62 — пин 6 модуля это `RXEN`, им управляет RadioLib;
  - `3` = E22P-868M30S — пин 6 это `EN`, общий включатель тракта. RadioLib пины RF-ключа не получает (`setRfSwitchPins(NC, NC)`), нога держится высоким вручную.
- Выбор влияет и на ETA (модель питания берёт токи модуля), и на RF-тракт.
- Правка, касающаяся железа, всё равно делается **одинаково для всех ролей**: нельзя поправить только BLE-компаньон и забыть репитер.

### Как переключить модуль

- **Компаньон:** настройки → `[ Darktec ]` → `Radio mod`, значения `E22-33S` / `E22-30S` / `RA62` / `E22P`. Применяется сразу: меняются и RF-тракт, и модель питания.
- **Любая роль с CLI** (репитер, комната, сенсор, компаньон — в том числе через Remote CLI):
  ```
  set radio.module 0     # 0=E22-33S, 1=E22-30S, 2=RA62, 3=E22P
  get radio.module       # проверить, что встало
  ```
  Выбор сохраняется в `/darktec.prefs` и переживает перезагрузку.
- **KISS-модем и terminal_chat** своего CLI/меню не имеют: они читают `/darktec.prefs` при старте, но поменять модуль из ноды нечем.
- Что происходит на уровне железа: для `0..2` вызывается `setRfSwitchPins(2, NC)` — пин 6 снова `RXEN` под RadioLib; для `3` вызывается `setRfSwitchPins(NC, NC)` и пин 6 держится высоким вручную (`EN`). Модель питания (ETA) получает тот же индекс.

### Подменю `[ Darktec ]` и файл `/darktec.prefs`

Настройки DarkTec живут в отдельном бинарном файле `/darktec.prefs` (`DarktecPrefsFormat.h`: 28 байт, magic `DRTC`, версия 6, CRC16), а не в `/prefs.json` ядра — чтобы правка не переписывала ядровые настройки.

- Пункты: `Capacity` (RealCap → пользовательская → 4000 → 3000), `Cap low` (3.0/3.2/3.4 В — нижняя точка старта цикла RealCap), `Screen on` (15s/30s/1m/5m/1h), `Brightness` (Low/Mid/High = контраст 1/127/255), `Bar` (NF или % заряда в мини-баре заставки), `V-Cut` (порог отключения), `Radio mod`, `RAM`, `Back`. Пользовательская показывается числом, которое задал прошивальщик; `RealCap` — словом (число видно на странице ETA). **Навигация — как в остальных меню:** долгое нажатие листает значение, короткое ведёт курсор вниз, двойное выходит из подстраницы; отдельного режима правки со скобками нет.
- **Скорости NF в меню нет и в prefs она не хранится.** При старте всегда 100 мс; менять на ходу — тройным нажатием на экране шума (в RAM до перезагрузки). Байт в `/darktec.prefs` оставлен ради совместимости формата, но всегда пишется нулём.
  - `UserPref` — ёмкость `capacity_mah` (1000..10000, любое число), её задаёт прошивальщик командой `set darktec.capacity N`; `3000`/`4000` — фиксированные; `RealCap` — измеренная ёмкость из ETA-страницы (`real_cap_mah`), пока не измерена — берётся пользовательская. Фактическая ёмкость = `effectiveCapacityMah()`.
  - От неё масштабируются остаток и ETA (кривая SOC привязана к напряжению, а не к ёмкости).
- Файлы версий 1 (beeline 1.18.0), 2 (наш первый перенос), 3, 4 и 5 читаются и конвертируются: порядок модулей и режим ёмкости переводятся, яркость у них ставится High, у v5 нижняя точка RealCap — 3.4 В.
- Реле T2 (`RELAY`) в этот файл не входит: состояние намеренно не сохраняется.
- **Порог низкого напряжения** (`low_batt_mv100`, байт 13, в единицах 100 мВ, 0 = штатные 3.40 В) читается в `DarktecBoard::begin()` сразу после prefs и кладётся в `LowBattGuard`. Проверка батареи в `main()` идёт уже после `board.begin()`, поэтому стендовое значение переживает перезагрузку. `power_screens::batteryFlat()` при переопределении игнорирует штатное правило «ниже 2.5 В — значит батареи нет».
- `board.setDisplayOn()` вызывается из UI при включении/выключении панели — от этого зависит ток покоя в ETA.

### CLI для конфигуратора (прошивальщика)

Команды принимаются по USB. **Компаньон** разбирает CLI сам (`MyMesh::handleCommand`) и до `CommonCLI` не доходит, поэтому команды DarkTec живут в `DarktecBoard::handleCommand` — там их видят все роли.

```
set radio 869.900,62.5,8,6   # канал сети одной строкой: частота, полоса, SF, CR
set tx 22                    # мощность -9..22 dBm
set adc.multiplier 1.750     # коэффициент АЦП
set radio.module 0..3        # модуль; 0=33S, 1=30S, 2=RA62, 3=E22P
get radio.module             # проверить, что записалось
set darktec.capacity 4500           # пользовательская ёмкость 1000..10000, режим → UserPref
set darktec.capmode real|user|3000|4000  # режим ёмкости
set darktec.caplow 3.0|3.2|3.4      # нижняя точка цикла RealCap, В
set darktec.lowbat 1.0              # порог отключения по низкому напряжению, В (1.0..4.0), пишется в prefs
set darktec.lowbat off              # вернуть штатные 3.40 В
get darktec.lowbat                  # > 1000 mV / > default 3400 mV
reboot                       # применить частоту/полосу/SF/CR
```

`set name` — в `MyMesh` (компаньон) и `CommonCLI` (остальные). `radio`/`tx` — в `CommonRadioPrefs`, применяются после `reboot`. `radio.module` и ёмкость — сразу и сохраняются в `/darktec.prefs`.

**Как прошивальщик общается с нодой:** компаньон — бинарными кадрами (`<` + len16 + payload, payload[0]=66 `CMD_RUN_CLI_COMMAND`, ответ `>` + len16 + payload[0]=29), остальные роли — обычным текстом. Перед отправкой полезно спросить `ver` и найти порт по ответу: на компьютере может быть чужая nRF52 с тем же VID `0x239A`/`0x1915`.

### Ловушка с номерами пинов

На плате два способа нумерации, и в `platformio.ini` рядом соседствуют оба. Проверять `g_ADigitalPinMap` в `variant.cpp` перед любой правкой пинов.

| Нога nRF | Arduino-пин | Занято под |
|---|---|---|
| P1.00 | 6 | `PIN_USER_BTN` / `PIN_BUTTON1` |
| P0.11 | 7 | `PIN_BOARD_SCL` → `Wire.setPins()` |
| P1.04 | 8 | `PIN_BOARD_SDA` → `Wire.setPins()` |
| P0.24 | 5 | **T1** — `PIN_GPS_EN` |
| P0.08 | 0 | **T2** — гейт VT3, **реле** (`DARKTEC_RELAY_PIN=0`, ключ `RELAY`) |
| P0.06 | 1 | **T3** — `PIN_BUZZER`, гейт VT4 |
| P0.17 | 2 | EN модуля E22P (у E22 — RXEN) |
| P0.13 | 21 | `SX126X_POWER_EN`, `PIN_EXT_VCC` |
| P0.31 | 17 | `PIN_VBAT_READ` / `PIN_BATTERY` |
| P0.03 / P0.04 | 3 / 4 | `PIN_GPS_RX` / `PIN_GPS_TX` |

**Устаревшие определения в `variant.h`:** `PIN_WIRE_SDA=6` / `PIN_WIRE_SCL=7` и `PIN_SERIAL1_TX=1` / `PIN_SERIAL1_RX=0` в сборке не используются. Реальная шина I2C задаётся в `DarktecBoard.cpp` через `Wire.setPins(8, 7)` — SDA `P1.04`, SCL `P0.11`. Определения Serial1 указывают на те же ноги P0.06 (буззер) и P0.08 (реле): **если буззер замолчал или заквакал странно — проверять, не поднялся ли Serial1 на P0.06.**

### Транзисторы (по схеме V2.1)

Четыре мосфета: три N-канальных `IRLML6344` (VT2, VT3, VT4) с резисторами 10 к на затворах (R30–R32), плюс `VT1` — P-канальный `AO3401A` во входной цепи зарядника CN3795 (защита от переполюсовки).

| Имя в прошивке | Схема | Нога MCU | Arduino-пин | Что коммутирует |
|---|---|---|---|---|
| **T1** | VT2 (IRLML6344) | P0.24 | 5 | GPS: `-D PIN_GPS_EN=5` |
| **T2** | VT3 (IRLML6344) | P0.08 | 0 | **реле**: `DARKTEC_RELAY_PIN=0`, ключ `RELAY` |
| **T3** | VT4 (IRLML6344) | P0.06 | 1 | **буззер**: `-D PIN_BUZZER=1` |

- «T1…T3» — шелкография платы, `VT2…VT4` — позиционные обозначения.
- **T3 работает, писать ничего не нужно.** `-D PIN_BUZZER=1` задан во всех companion-env. Отдельного `PIN_BUZZER_EN` нет — включателем служит сам транзистор.
- **T1 занят под GPS** (`PIN_GPS_EN`).
- Обвязка питания: делитель VBAT 100к/100к на P0.31, шунт 50 мОм (`TELEM_INA3221_SHUNT_VALUE 0.050`).

### Удалённо управляемый выход RELAY (T2)

Реле на T2 управляется **штатным механизмом настроек сенсоров** — протокол, приложение и каналы не трогались. Реализация целиком в `variants/darktec/DarktecSensorManager.h`, общий код для всех ролей.

```
sensor set RELAY ON | OFF | TOGGLE     ->  "RELAY: ON" / "RELAY: OFF"
sensor get RELAY                       ->  "> ON" / "> OFF"
sensor list                            ->  RELAY=... (и прочие настройки)
```

- Принимаются также `1`/`0`, `true`/`false`, `yes`/`no`, синоним ключа `t2`.
- **При старте реле всегда выключено** — требование безопасности для силовой нагрузки. Состояние намеренно НЕ сохраняется в prefs.

Как команда доходит до ноды:

| Роль | Путь |
|---|---|
| Репитер | личка от админа → CLI (`simple_repeater/MyMesh.cpp`) |
| Комнатный сервер | личка/пост от админа → CLI (`simple_room_server/MyMesh.cpp`) |
| Сенсор | личка от админа → CLI (`simple_sensor/SensorMesh.cpp`) |
| Компаньон | **Remote CLI**: личка вида `<CLI-PIN> <команда>` (`companion_radio/MyMesh.cpp`) или канал `TerminalCLI` |
| Любая роль от приложения | serial/BLE `CMD_SET_CUSTOM_VAR` в формате `RELAY:ON` (`companion_radio/MyMesh.cpp`) |

**Remote CLI у компаньона** — основной путь удалённого управления: PIN — 8 hex-символов от последних 4 байт **приватного** ключа (из публичного не выводится), смотреть командой `pin`, включается `set remote.cli on/off` (по умолчанию включено). Ответ приходит личкой, длинный режется на чанки `[1/N]`. Регистр в CLI важен: `sensor` — строчными.

**Про «приватные» каналы:** канал в MeshCore — групповой на общем PSK, а не адресная переписка. У `TerminalCLI` PSK фиксированный и публичный (`MyMesh.h`). Для секретных команд — только Remote CLI по личке.

**Не сделано осознанно:** ключ `GPSPWR` для T1 зарезервирован, но возвращает `false`. `setSettingValue("gps", ...)` управляет только данными, а чипу GPS после подачи питания нужна пауза на старт — иначе детект GPS сломается. Делать это надо вместе с драйвером GPS.

### Сборка и UF2

- PlatformIO живёт в `%USERPROFILE%\.platformio\penv\Scripts\pio.exe`, в PATH его нет.
- `pio run -e <env>` — сборка. Первая после чистого клона качает тулчейн (~15 минут), дальше один env ~35 с.
- Если падает `MissingPackageManifestError` или «библиотека не найдена» — удалить `.pio/libdeps/<env>` и запустить `pio pkg install -e <env>`.
- **`pio run` НЕ создаёт `.uf2`.** Он делает `firmware.elf`, `firmware.hex` и `firmware.zip` —
  это **пакет Nordic DFU для обновления по воздуху** (OTA, бутлоадер OTAFIX). Цель
  `-t create_uf2` его не создаёт, поэтому на релизе каждую роль собираем ещё и обычным
  `pio run -e <env>`.
- UF2 получается целью `create_uf2` (`pio run -e <env> -t create_uf2`) или скриптом `build-darktec-uf2.ps1`, кладётся в `out\uf2\` (каталог в `.gitignore`).
- Проверка настоящего UF2: первые 4 байта `55 46 32 0a`, familyID (байты 28–31) `40 28 a5 ad` = `0xADA52840`, размер кратен 512.
- **Кириллица в пути ломает `create_uf2`** (`uf2conv.py: error: unrecognized arguments`). Путь проекта — без кириллицы. Обход: `python bin\uf2conv\uf2conv.py <hex> -c -o <uf2> -f 0xADA52840`.
- **ExecutionPolicy = Restricted** — `.ps1` напрямую не запускается: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-darktec-uf2.ps1 -Env <env>`.

**Имя готового файла: `<env>-v<версия>-<хеш>.uf2`.** В `out\uf2\` UF2 называется так: `Darktec_companion_radio_ble-v1.18.0d10-7e3d1429.uf2`, `Darktec_repeater-v1.18.0d10-<хеш>.uf2`. Хеш — 8 символов коммита, с которого собрано (тот же, что в строке `[git_version]` и в образе после `v1.18.0dN-`). Ни даты, ни времени, ни `-e22` в имени нет.

- Исключение — сборка с ветки `lr2021`: она затёрла бы файл E22, поэтому префикс ветки ставится спереди: `lr2021-Darktec_companion_radio_ble-v1.18.0d10-1ee64d6f.uf2`. Перед `<env>` и только он.
- Устаревшие сборки в `out\uf2\` не копятся: новая версия — новый хеш в имени, старые файлы удаляются, чтобы не было двух «почти одинаковых».
- Релизный ассет на GitHub называется иначе — `<env>.uf2` (без версии и хеша). Это имя даёт `tools/make_release.py` при загрузке; локальный файл переименовывать для этого не нужно.
- DFU-пакет (`.zip` из `pio run`) — `<env>-v<версия>-<хеш>.zip`.

### Правило: каждая сборка обязана оставаться патчимой

DarkFlasher вшивает настройки прямо в образ. Значит **любая прошивка, которую мы
собираем (тестовая или релизная), обязана сохранять блок заводских настроек** —
иначе кнопки «Собрать UF2» / «Собрать OTA-ZIP» откажут, и это всплывёт на релизе.
Проверять после каждой сборки, а не «потом».

- Блок: `variants/darktec/DarktecFactoryCfg.h/.cpp`, 152 байта, метка
  `DARKTEC-FACTORY\x01` (15 байт текста + `0x01`), дальше версия, длина, CRC32 и
  128 байт полезной части.
- **Метка в образе должна встречаться ровно один раз.** Копия метки (массив,
  строка, отладочный дамп) — сразу второй кандидат, и строгая проверка ломается.
  Именно поэтому в `isValid()` сравнение идёт с литералом посимвольно, без
  массива-константы. Уже один раз на этом обожглись в d7.
- **Блок лежит внутри образа** (`.rodata.factory_cfg`), а не отдельной страницей
  в конце: так патч — это замена байт, без пересчёта `numBlocks` в UF2.
- Секцию держит от `--gc-sections` обращение к `DarktecFactoryCfg::blob()`
  в `DarktecBoard::begin()`; убирать его нельзя — блок пропадёт из образа.

**Чек-лист после сборки:**

```
python tools/check_factory_cfg.py            # все 8 env из .pio/build
python tools/check_factory_cfg.py --dir out/uf2
```

Ожидаемо: у шести ролей `OK ок: блок 0x… (v1, длина 0)`, у `kiss_modem` и
`terminal_chat` — `блока нет — так и задумано`. Любой `FAIL` или «меток 2» —
сборку не выкладывать.

**Если добавляешь новую роль или env:**

1. Добавить вызов в `main.cpp` после `the_mesh.begin()` (или `begin(fs)`):
   ```cpp
   #ifdef DARKTEC
     NodePrefs* np = the_mesh.getNodePrefs();
     if (board.applyFactoryConfig(*np)) {
       the_mesh.savePrefs();
       if (board.factoryRadioChanged()) {
         radio_driver.setParams(np->freq, np->bw, np->sf, np->cr);
         radio_driver.setTxPower(np->tx_power_dbm);
       }
     }
   #endif
   ```
2. Добавить env в `ENVS` в `tools/check_factory_cfg.py` и прогнать проверку.
3. Если у роли свой тип настроек (как у `terminal_chat`) — либо переводить её на
   общий `helpers/NodePrefs.h`, либо вписать в `NO_BLOCK` с объяснением.

**Если меняешь раскладку блока** (добавил поле, сдвинул смещения):

1. Поднять `kVersion` в `DarktecFactoryCfg.h`.
2. Синхронно поправить DarkFlasher: `FACTORY_VERSION`, `pack_factory_payload`,
   флаги `FLAG_*` в `DarkFlasher.py` — иначе старый флешер откажется, а новый
   запишет мусор в чужую раскладку.
3. Прогнать проверку и собрать один файл с настройками, чтобы убедиться, что
   прошивка их читает.

**Как это работает в прошивке**

- `DarktecBoard::applyFactoryConfig(NodePrefs&)` сверяет CRC32 с полем
  `factory_crc` в `/darktec.prefs`; после применения CRC запоминается, и блок
  больше не срабатывает. Настройки, поправленные потом руками, живут своей жизнью.
- Радио перестраивается сразу (`setParams` / `setTxPower`), без перезагрузки.
- Флаги: имя, радио, ёмкость, модуль — что задано, то и применяется; пустое поле
  не затирает настройки пользователя.
- `NodePrefs` в `DarktecBoard.h` — только предобъявление: у `simple_secure_chat`
  свой `struct NodePrefs`, подключать туда `helpers/NodePrefs.h` нельзя (была
  редукция структуры).
- `kiss_modem` настроек не имеет вовсе, `terminal_chat` живёт на своём типе prefs —
  этим двум вшивание недоступно, флешер так и говорит.

### Гибернация: без SYSTEMOFF (важно)

**SYSTEMOFF не используем.** В нём разбудить чип можно только по GPIO-детекту,
LPCOMP, NFC или VBUS — **pin-reset (кнопка RST) оттуда не поднимает**, и нода
выглядит мёртвой до передёргивания батареи. Клиент ловил именно это.

Как сделано (`DarktecBoard::powerOff`):

- ждём отпускания кнопки (с таймаутом 5 с — раньше был бесконечный `while`,
  залипший LOW подвешивал ноду);
- `shutdownPeripherals()` — панель, радио, GPS; плюс `SX126X_POWER_EN` в LOW;
- **гасим BLE-стек** (`sd_softdevice_disable()`), иначе SoftDevice будит ядро на
  каждый интервал рекламы и держит радио;
- на кнопку навешиваем событие GPIOTE (HiToLo), выключаем тик `SysTick`, уходим
  в `__WFE()`;
- RST — обычный сброс чипа (ядро живое). **BTN спящую ноду не будит**
  (`DARKTEC_HIBERNATE_BTN_WAKE=0` в `variants/darktec/platformio.ini`) — по
  просьбе, чтобы включение было однозначным; вернуть кнопку — поставить `=1`
  или убрать флаг (тогда на неё вешается событие GPIOTE).

Цена: ток в гибернации выше, чем у SYSTEMOFF (замер на макете ~38 мА при
погашенной панели). Уменьшать — отдельная задача: смотреть INA3221, подтяжки,
USB-периферию.

`NRF52Board::shutdownPeripherals()` гасит панель **всегда** (`setContrast(0)` +
`turnOff()`), а не только когда `isOn()`: логически погашенный OLED оставлял
включённым charge pump.

### Модель питания: SOC из напряжения, ETA интегрированием

Три принципа:

1. **Процент берётся из напряжения по реальной кривой разряда**, а не линейно между пустым и полным. Кривая снята с живой банки на токе 100 мА, в прошивке — 21 точка с шагом 5% (`SOC_CURVE_SHAPE`).
2. **ETA считается интегрированием по кривой**, а не делением остатка на средний ток: ток ноды сам зависит от напряжения (25.7 мА при 4.2 В против 50 мА при 3.0 В на 33S).
3. **Залитые мАч в SOC и ETA НЕ участвуют.** Нода заряжается от 55–70%, поэтому процент берётся из напряжения. Счётчик заряда — только «залито за сессию» для страницы INA.

Сглаживание и заряд:

- **SOC сглаживается** EMA (α=0.05, τ≈5 с при тике 250 мс): одиночный шумный замер не должен дёргать остаток в мАч.
- **ETA сглаживается** EMA (α=0.02) плюс ограничение прыжка за тик — не быстрее 1% (и не меньше 1 минуты). Иначе смена скважности перебрасывает прогноз на часы одним кадром.
- **ETA на заряд** — `etaChargeMinutes()`, но не от напряжения, а **кулоновским счётом**: в момент подключения зарядника остаток фиксируется (`_charge_mah = capacity * SOC`), дальше к нему прибавляется измеренный ток пакета каждый тик. Пока идёт заряд, `SOC` и `REMAIN` берутся из этого счётчика, а не из кривой напряжения — под 2 А клеммы подняты почти до 4.2 В и кривая врёт. Как только заряд кончился, `SOC` снова считается по напряжению.
  ETA = `(capacity − _charge_mah) / I_eta`, где `I_eta` — **средний ток за сессию заряда** (`накоплено / прошедшее время`), а не мгновенный: на CV-фазе мгновенный падает и прогноз прыгал с 14 до 44 минут. Средний меняется плавно, поэтому «сказано час — значит час» (проверено симуляцией: 60 → 0 минут без скачков вверх).
  **Хвост не прогнозируем.** Как только ток упал ниже 150 мА (это ровно порог «вилки»), ETA обнуляется и на экране пишется `ETA    CHG done`: последние ~100 мАч заливаются часами, честного числа там нет. Растяжка после 80% удалена. Ток — `Inow +мА`.

Как устроено:

- **Напряжение берётся только в покое**: под передачей 1.5 А клеммы просажены, а в полке кривой 3–5 мВ на 1% SOC. Модель игнорирует напряжение, пока в эфире была активность менее 3 секунд назад (`OCV_QUIET_MS`).
- **Ток — двумерная интерполяция**: по напряжению (4.2 / 3.7 / 3.0 В) и по мощности передатчика (−9 / 0 / 5 / 10 / 22 dBm).
- **Скважность передачи** измеряется по факту (`onAfterTransmit` → `noteTxTime`), окно 10 минут.
- **Окно напряжений по химии**: низ всегда 3000 мВ, верх — по `BATTERY_CHEMISTRY` (Li-ion 4200, LiFePO4 3650, LTO 2500).

#### Заряд: компенсация падения на внутреннем сопротивлении

Под зарядом 2 А клеммы пакета поднимаются почти до 4.2 В независимо от реального заряда: банка при 50% показывает 4.14 В, и без компенсации нода рисует 100%.

- Решение: `V_банки = V_изм − I·R`, дальше как обычная разрядная кривая.
- `R = 0.2448 Ом` — измерено сравнением зарядной и разрядной кривых при одинаковом SOC.
- `IR_K = 1.05` — подбор; средняя ошибка SOC +0.7%, разброс −2.2…+3.9%.
- Зарядная кривая 2 А лежит в таблицах как `CHARGE_CURVE_2A` — для справки.
- **Во время заряда замер берётся сразу**, не дожидаясь тишины: ток заряда перебивает передачи, а компенсация делает замер пригодным.
- **Признак заряда — два условия сразу:** напряжение шины CHRG выше 4.5 В (зарядник подключён — та же шина, по которой рисуется значок) **и** модуль тока пакета выше 20 мА. Пока зарядник подключён, состояние заряда держится защёлкой: в хвосте ток падает и без неё экран прыгал бы между «CHG done» и разрядным прогнозом.
- **Знак тока не используется нигде.** Раньше модель угадывала полярность шунта один раз при старте (`learnCurrentPolarity`) — и если нода включалась уже на зарядке, знак запоминался наоборот: разряд 40 мА принимался за заряд и на экране висело `Inow +44mA` с `ETA CHG done`, а настоящий заряд 1.5 А — за разряд. Сейчас знак нужен только для компенсации, и он берётся из состояния заряда, а не из измерения. Регресс-тест: `python tools/check_charge_state.py`.
- **Ток и флаг заряда обновляются каждый тик**, а не после паузы тишины в эфире: иначе `Inow` показывал застывшее число, пока радио слушает трафик. Пауза 3 с осталась только для напряжения (SOC).

#### О чём ещё надо помнить

- **Значок батарейки берёт процент у модели** (`board.getSocPercent()`), а не из линейного пересчёта. Если модель ещё не получила замер — падение на линейную оценку, чтобы значок не мигал пустым на старте.
- **Индикатор заряда слева от значка** считается по шине CHRG (`DarktecBoard::loop`, `getChargeIndicator()`), а не по проценту батареи: напряжение шины CHRG выше 4.5 В — зарядник подключён; дальше смотрим ток **пакета** (канал BATT, по модулю): выше **165 мА** — **молния** (идёт заряд), ниже **150 мА** — **вилка** (заливка закончилась, зарядник держит подпитку). Между 150 и 165 мА значок **не меняется** — это гистерезис 15 мА (`DARKTEC_CHARGE_ICON_MA` / `DARKTEC_CHARGE_ICON_OFF_MA`), без него иконка дребезжала на границе: ток плавает на ±10 мА. Порог 120 мА был слишком низким — молния держалась долго после окончания заливки. Шины CHRG ниже 4.5 В — иконки нет. **Приоритет у USB:** если воткнут кабель в USB самой ноды (`board.isUsbConnected()`), вместо молнии/вилки рисуется белая плашка `USB` (24×10, буквы чёрные, скругление 2 px лесенкой — драйвер умеет только `fillRect`), чтобы две иконки не накладывались. Имя ноды обрезается многоточием по левой границе зоны иконок (`headerIconsLeft()`), иначе длинное имя наезжает на значки. **Смена иконки сама просит кадр** (`_last_icon_state` в `UITask::loop()`): иначе на статичном экране (настройки, часы) молния появлялась бы только при смене страницы. В том же слоте живёт **`RX`/`TX`** (`_rxtx_mode`): на время активности он **уступает место** — молния, вилка и плашка USB на эти сотни миллисекунд убираются и потом возвращаются. Горит последний, кто был (TX перекрывает RX, пока идёт передача); RX — импульс 750 мс по счётчику `getPacketsRecv()`, TX — 450 мс после `isRadioTxBusy()`. **Точки-пульса больше нет**: её рисовал `DarktecDisplay` между кадрами, она загоралась раньше интерфейса и на всех экранах — удалена вместе с `statusDotWanted()`. В беззвучном режиме значок беззвучки сдвигается левее всех.
- **На странице батареи `Inow` — из модели, а не с INA3221.** INA на этой плате потребление системы **не видит**: шунт стоит в цепи пакета, и на разряде там единицы миллиампер шума (4–6 мА при реальных 28–50). Поэтому ток берётся из таблиц замеров по режимам: строка — состояние экрана (выкл / заставка / вкл), столбец — передача или приём, интерполяция по напряжению (`currentNowMa()`). Под зарядом показывается измеренный ток пакета со знаком `+`: зарядный ток шунт видит нормально.

#### Ограничения

- **В полке кривой (30–50% SOC) 3–5 мВ на 1% SOC**, а напряжение меряется делителем 100к/100к через АЦП nRF52. Точность упирается в железо. Точнее было бы брать напряжение с INA3221 — не сделано.
- **ETA зависит от наблюдаемой скважности** за последние 10 минут, а не от будущего трафика.
- Модель тика кормится раз в 250 мс.

### Интерфейс компаньона

Все правки — в `examples/companion_radio/ui-new/UITask.cpp` и `UITask.h`.

**Заставка:**

```
    [логотип MeshCore]        y=3
    Dark Electronics          y=20
    v1.18.0 #0eebaf2d         y=30
    17 Oct 2026               y=42
```

- **Версия и номер коммита — одной строкой.** Метка сборки (`SE`) больше не разделяет модули — модуль теперь настройка, а номер говорит о ревизии кода. `v1.18.0 #0eebaf2d` = 17 символов при 21 влезающих.
- Строка собирается в `_version_line[22]`: база версии плюс `#` и хвост после дефиса. Если хвоста нет — подставляется `_build_tag`.
- **Дата сборки живая:** `git_version.py` подставляет `FIRMWARE_BUILD_DATE` на каждом `pio run`. Жёсткое `"14 Aug 2026"` в `MyMesh.h` — только запасной вариант.
- **Проверка после сборки:** строка `[git_version] GIT_COMMIT = <хеш>` в выводе `pio run`. Нет её — на заставке будет версия без номера.
- `FIRMWARE_VERSION_SUFFIX` теперь всегда `SE` и служит только запасным вариантом `_build_tag`.

**Иконки 8×8** (`examples/companion_radio/ui-new/icons.h`) — формат Adafruit `drawBitmap`: **байт = строка**, старший бит = левый пиксель, строки сверху вниз. Раньше редактор макетов считал «байт = столбец», и макеты показывали иконки повёрнутыми — теперь `screenui.Screen.xbm` понимает формат так же, как прошивка.

**Время горения экрана:** пункт `Screen on` в подменю `[ Darktec ]`, значения 15s / 30s / 1m / 5m / 1h, массив `AUTO_OFF_MS[5]`, индекс — `auto_off_idx` в `/darktec.prefs`.

**`Always On` (меню `Экран`, `_clock_dim_mode`) — это заставка «часы + мини-бар».** Когда включена и таймер `Screen on` истёк, экран не гаснет: включается заставка с контрастом 1 (блок 90×34: часы шрифтом 3, сразу под ними строка значков — заряд, значение из пункта `Bar`, конверт с числом непрочитанных, `RX`/`TX` у правого края; разделительной линии нет). **Значение печатается без префикса** (`-105` или `85%`): с конвертом и числом непрочитанных подпись `NF:-105` в 90 px упиралась в иконку. **Содержимое бара центрируется под часами** — шрифт моноширинный (`6 px` на знак, у всех глифов 32..255 `xAdvance = 6`), поэтому ширина считается целыми числами: `6·len` для текста, 8 px иконка, 9 px конверт с зазором. Слот `RX`/`TX` в ширину **не** закладывается: буквы появляются справа от центральной группы, и группа при вспышке не едет; если буквы не влезают справа — группа прижимается влево. Непрочитанных не больше `MAX_UNREAD_MSGS = 64`, то есть максимум две цифры. Блок гуляет по экрану по 1 px в секунду и отбивается от краёв; контраст 1 переставляется каждый кадр, чтобы панель не вспыхнула. Долгое нажатие на экране часов включает и выключает заставку (та же настройка ui_clock_dim_mode, что «Экран → Часы всегда»). Нажатие кнопки только выводит из заставки (действие не выполняется), яркость возвращается из `[ Darktec ]`. Входящее сообщение выводит из заставки, а когда таймер «Время показа» истёк — `onPreviewTimeout()` возвращает в заставку сразу. Живёт в `UITask::enterSaver/exitSaver/renderSaver`.

- Все места, где продлевался таймер, используют `autoOffMillis()` (читает prefs).
- Экраны зовут `_task->extendAutoOff()`, а **не** трогают `_auto_off` напрямую — это приватное поле `UITask`.

**Входящие сообщения:** показываем только с **первой** страницы главного экрана и ровно на «Время показа» из настроек (`Chat → Show Time` = 5с / 15с / 30с, `msgHoldMillis()`). **При «Выкл» превью не появляется вообще** — сообщение только копится в непрочитанных, экран и заставка не трогаются.

- Признак «первая страница» — `curr == home && !isOnClockPage()`. На странице CLOCK своя логика (инлайн-показ PM по настройке `PM CLOCK`).
- С других страниц сообщение копится в непрочитанных, экран не трогаем.
- Автоскрытие: `MsgPreviewScreen::armAutoDismiss()` + `poll()`; флаг `_on_screen` ставится в `UITask::setCurrScreen()` — уход с экрана отменяет автоскрытие.
- **Режим истории автоскрытие выключает.**
- `poll()` у экранов вызывается из `UITask::loop()`.

### Экраны компаньона (только у компаньона)

| Экран | Что показывает |
|---|---|
| **шум** (`HomePage::NOISE`, `UI_NOISE_PAGE`) | дорожка шумового пола или SNR: 64 столбика, сглаживание по 3 точкам, автоскейл, две независимые истории. Внизу инверсная полоса, разбитая на три ячейки: `NF:-105 | ^-101 | v-109` — стенки на 44 и 86 px, вторая и третья ячейки равные по 41 px, содержимое обеих сдвинуто на 2 px от стенки (текст с 48 и с 90); во второй знак `^` печатается отдельно, а число сдвинуто ещё на 1 px правее. На SNR подпись полная (`SNR:-13.0 | ^-11.0 | v-15.0`) и стенки другие — 54 и 91 px: двузначное `SNR:-13.0` это 54 px. **Пробел после `:`, `^` и `v` ставится только перед положительным числом** — у отрицательного минус уже отделяет, а лишний знак вылезает за стенку. `^`/`v` вместо стрелок, потому что стрелок 0x18/0x19 в кириллическом шрифте нет. **Долгое нажатие BTN переключает NF ↔ SNR**, **тройное — скорость** (`NF Speed` = 100 / 250 / 500 / 1000 мс; при старте всегда 100 мс, в prefs не пишется); на этом экране тройное не глушит буззер (`UIScreen::isOnNoisePage()`). Данные копит `HomeScreen::serviceNoise()` из `UITask::loop()` — всегда, даже при выключенном экране и на других страницах. SNR пишется по счётчику принятых пакетов (`radio_driver.getPacketsRecv()`) и усредняется за окно 500 мс: одно сообщение в меше приходит 2–4 раза, без усреднения график — пила |
| **INA** (`HomePage::INA`, `UI_INA_PAGE`) | два рельса INA3221 — батарея и зарядник: напряжение, ток, мощность, «залито за сессию». Таблица в рамке: три числовых столбца одной ширины по 32 px (V/A/W), линии столбцов продолжены в инвертированную шапку, под строками линия и счётчик `CHARGED`. Верх таблицы — `content_y - 1`: на OLED иначе пропадал зазор между `CHARGED` и нижней линией. Значения >9.99 печатаются с одним знаком после запятой |
| **радио** (`HomePage::RADIO`) | частота, полоса, SF, CR, мощность передатчика и **SNR** в строке `TX:22dBm  SNR:-7.5`, ниже — текущий шумовой пол |
| **батарея** (`HomePage::BATT`, `UI_BATT_PAGE`) | напряжение, SOC от модели, остаток в мАч, ETA (под зарядом — до полного, `ETA CHG`, в хвосте `ETA CHG done`), **ток `Inow` из модели** (под зарядом — измеренный ток пакета со знаком `+`) |

У репитера, комнаты, сенсора, KISS-модема и terminal chat этих экранов нет — своя простая отрисовка.

**Третий экран в стопке шума — «шум за сутки».** Долгое нажатие на странице шума листает по кругу: живой шум → SNR → сутки → живой шум (`noise_mode` 0/1/2). Суточный график: 128 столбцов = 24 часа (~11 мин 15 с на столбец), линия 1 px, разрывы там, где данных нет, автошкала по накопленному (мин…макс с запасом 2 dB, но не уже 10 dB), снизу инверсная полоса с часами `00 06 12 18` и стенками между шестичасовыми блоками, текущий момент — пунктирный столбец. Выборка — среднее за 10 секунд (отсчёты шумового пола берутся раз в 500 мс), столбец — среднее по своим выборкам. Ноль от ядра (пол ещё не измерен) не копится — такой отсчёт просто пропускается, а окно усреднения при этом **не сбрасывается**: иначе серия нулей (например, пока после `resetAGC` пол не пересчитан) съедала целые столбцы и график выходил рваным. Живёт только в RAM: после перезагрузки график начинается с текущего часа. Стирается только при настоящем переходе через полночь (`minute + 720 < day_last_min`), а не при любой коррекции часов назад — синхронизация времени с приложением или GPS на пару минут раньше обнуляла накопленный день. Рисуется раз в минуту — чаще незачем, столбец всё равно живёт 11 минут.

**Третья страница экрана «батареи» — uptime, время с зарядки, измеренная ёмкость.** Долгое нажатие на экране батареи — третья страница: `UpTime` (uptime с загрузки, `00d:00h:00m`), `LastCHRG` (время с конца последней зарядки, тот же формат; хранится в prefs как Unix-время, до синхронизации часов — по счётчику с загрузки) и `RealCap` (измеренная ёмкость пакета или `no data`). Подпись слева, значение прижато к правому краю — `LastCHRG` (8 знаков) и `00d:00h:00m` (11) в общий столбец не влезают. Ёмкость меряется циклом: разряд до выбранного порога `Cap low` (3.0 / 3.2 / 3.4 В), затем заряд до 4.15 В при измеренном токе ниже **200 мА** — тогда накопленный заряд сессии и есть реальная ёмкость. Считается **чистый ток в банку**: из измеренного вычитается собственное потребление ноды (`currentNowMa()`), потому что INA видит весь ток от зарядника, а нода питается от него же. Порог разряда сравнивается с напряжением покоя (`_ocv_mv`), а не с сырым замером, иначе просадка под передачей ложно засчитывала бы «дошли до порога». Отметка «уже разрядились» и сам порог лежат в `/darktec.prefs` (v6) и переживают перезагрузку — на 3.4 В нода может выключиться раньше, чем воткнут зарядник. Результат пишется в `real_cap_mah` и обновляется только при полном цикле. В конце меню `[ Darktec ]` (перед `Back`) строка `RAM` — подпись слева, число (`121.8K`) значением, то есть у правого края, как у остальных пунктов: свободная память = остаток кучи до `__HeapLimit` (это низ двухкилобайтного стека) плюс освобождённые блоки `mallinfo().fordblks`. **Одного `fordblks` мало** — он видит только освобождённые куски и на живой ноде показывал 0.6K при куче в 121K: верх кучи отдаёт `_sbrk(0)` из core (`new.cpp`), вызов с нулём ничего не выделяет.

**Вторая страница экрана «радио» — счётчики и занятость канала.** Долгое нажатие на экране радио переключает обычный вид и статистику: `RXp`/`TXp` (принято/отправлено; до 99999 печатается как есть, больше — `124.3k`, от миллиона `1.2M`), `ERR-RX` (ошибки CRC), `BUSY` (занятость канала, %), `TX%` (своя скважность передачи за 10 минут из модели питания), `NFd` (средний шум за сутки по накопленному суточному графику) и `SNR` (среднее по всему окну графика SNR — 64 точки, по одной на пакетное окно). Раскладка — две колонки по 11 знаков: левая с x=0, правая ровно с x=66, шаг строк `line_h` (11 px). Занятость считается по мгновенному RSSI: раз в 500 мс сравниваем `getLastRawRssi()` с шумовым полом +6 дБ, окно ~1 минута (счётчики половятся каждые 120 выборок). CAD не используется — он прерывает приём, а RSSI ядро и так меряет для шума.

**Шумовой пол на E22P:** снятая антенна даёт на экране NF около −76…−78 dBm, и это **не глюк прошивки**. У E22P в тракте приёма LNA, открытый вход (без антенны) шумит собственным трактом, чип честно отдаёт высокий RSSI. У E22 без LNA такого нет: там NF с уходом антенны падает к −100 и ниже. Проверять модуль без антенны только с 50-омной заглушкой, иначе замер бессмысленный.

### Энергопотребление: что выяснено (22.10.2026)

Замеры на стенде: ЛБП 4.2 В, амперметр в разрыве, тестовая прошивка `bench6` — **не в git** (`examples/darktec_bench/`, каталог в `.git/info/exclude`). Модуль E22-900M33S, мА:

| Состояние | мА |
|---|---|
| всё выключено: радио в сне, экран выкл, BLE не запущен | 17–18 |
| + INA3221 в работе | 17 |
| SoftDevice включён, рекламы нет | 21 |
| BLE реклама 152 мс / 20 мс | 21–22 |
| непрерывный приём | 29 |
| приём окнами 50 / 25 / 10% | ~21–27 |
| передача 22 dBm | 1391 |
| `PIN_EXT_VCC` в LOW («модуль обесточен») | 17 |
| **nRF52 в сбросе (RST зажат)** | **17** |

**Вывод: 17 мА — не ядро.** При зажатом RST чип не работает, а ток не меняется. По даташиту nRF52840 даже на полной загрузке (CoreMark) берёт максимум 9.1 мА, в покое — единицы. Ест пятиваттная линия: модуль E22 питается от BOOST 4.2→5.1 В, и **эта линия неотключаема** (VCC модуля приходит всегда, от неё же идёт RAW ProMicro, который делает 3.3 В). `PIN_EXT_VCC` (P0.13) этого рейла не разрывает.

**Следствия, чтобы не изобретать заново:**

- 28 дней автономности на этой плате недостижимы: 4000 мАч / 17 мА ≈ 9 дней при выключенном радио и ~5–6 дней в приёме. У конкурентов другой тракт питания, не прошивка.
- Радио в приёме добавляет 11 мА (33S) и 30 мА (E22P); передача 22 dBm — 1.4 А. Это не правится окнами приёма, пока пол 17 мА.
- Вклад экрана мал: заставка +2 мА, полный контраст в пределах шума замера.
- SoftDevice сам по себе +3–4 мА — по даташиту это много, но проверять это имеет смысл только после развязки по железу.
- Éсли когда-нибудь вернёмся к теме: нужен отдельный EN на 5 В модуля (или BOOST с shutdown) и модуль с низким током приёма. Тогда имеет смысл мерить поле ещё раз — тестовая прошивка для этого уже написана.
